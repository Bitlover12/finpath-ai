# FinPath 소비·카드 최적화 MVP

기준일: 2026-09-02

## 서비스 위치

소비·카드 최적화는 **FinPath 기본 금융분석 이후에 사용자가 선택하는 부가서비스**다.

기본 흐름은 소비분석 없이 완결된다.

1. 프로필 입력
2. 정책 자격판정
3. 일반저축 vs 기본 FinPath 비교
4. 정책·일반저축 월 배분
5. 목표 달성/미달 및 Goal Seeking
6. 실행 로드맵
7. **기본 FinPath 분석 완료**

그 뒤 사용자가 원할 때만 소비·카드 최적화를 실행한다.

8. CSV/XLSX 거래내역 업로드 또는 월 카테고리 직접입력
9. 소비 조정 What-if 및 카드 순혜택 계산
10. 추가 월 저축여력 산출
11. 늘어난 저축여력으로 기존 Eligibility / Optimizer / Goal Seeking 재실행
12. **일반저축 vs 기본 FinPath vs Full FinPath 최종 3-way 비교**

기본 FinPath 결과와 Full FinPath 결과는 별도로 저장한다. 소비 최적화 결과가 기본 분석을 덮어쓰지 않는다.

## 최종 비교 정의

- **일반저축**: 현재 월 저축액을 일반저축에만 적립한 결과
- **기본 FinPath**: 같은 월 저축액으로 정책·월배분·만기 재예치를 최적화한 결과
- **Full FinPath**: 소비 조정 + 카드 순혜택으로 늘어난 월 저축여력을 다시 FinPath 금융경로에 넣은 결과

Full FinPath는 선택형 시나리오이며, 소비 절감액은 사용자가 직접 정한 절감률을 적용한 가정이다.

## 소비·카드 계산 흐름

1. CSV/XLSX 거래내역 업로드 또는 월 카테고리 직접입력
2. 월 소비 카테고리 표준화
3. 사용자가 선택한 절감률을 배달·카페·쇼핑·구독·여가에 적용한 시나리오 계산
4. 현재 소비만으로 전월실적을 충족하는 체크/신용카드만 후보화
5. 혜택률·월 한도·연회비를 반영해 예상 월 순혜택 산출
6. 소비 조정액 + 카드 순혜택 개선액을 월 저축여력에 추가
7. 기존 금융엔진 전체 재실행

## 안전 원칙

- 카드 혜택을 받기 위해 소비액을 늘려야 하는 카드는 추천하지 않는다.
- 소비 절감액은 객관적 “낭비 판정”이 아니라 사용자가 직접 선택한 절감률을 적용한 가정이다.
- 카드 예상혜택은 발급 전 공식 상품설명서 확인이 필요하다.
- 업로드 거래내역은 분석에만 사용하고 서버에 영구 저장하지 않는다.
- 시장 전체 카드상품을 망라한다고 표현하지 않는다. MVP는 공식자료로 검증한 대표상품을 구조화해 비교한다.

## 향후 실제 계좌연동

상용화 단계에서는 사용자 동의 기반 오픈뱅킹/마이데이터 연동으로 거래내역을 자동수집할 수 있도록 소비분석 계층을 독립적으로 유지한다. 공모전 MVP에서는 CSV/XLSX 업로드와 직접입력으로 동일 분석 흐름을 시연한다.
